# 官方优化器热缓存实测

2026-11-21 在 Ryzen 7 9700X 上以 10 个 Chromium 计算 Worker 串行运行同一官方请求的各个版本。基线取上游发布 `9fd08b2202`，计算引擎 `d418682f5fce`，数据 `450ebd22f510`。候选引擎为 `8bcade14745b`，WASM 为 `14053539be20`。官方模板验收逐轮对照有序候选评分，再对照完整排名、配装及回放输入。保存的受限请求与上游完整输出逐项比较。时间包括本地 HTTP 下载、校验、解压、缺项补算、入围的 1,000 场复测和结果交付。 计时使用页面的任务规范化、Quick Fleet、Worker、IndexedDB 和分包读取器。测试关闭配装库投稿，服务器位置为本机回环地址。

## 受限起点

使用上游保存的另一份完整请求作独立验证。该请求采用四元素、空白起点、禁用一张 MOD 和一个赋能，仍在 25 目标、100% 爆头场景实算。默认模板用公开完整候选池生产。加入的赋能模板从公开可用赋能中去掉 `secondary_fortifier`，保留全部 MOD。宿主只使用这两份公开模板。私有请求仅用于对照结果。

## 宿主与流量

二十把武器分别覆盖单体、群体和三个爆头率，共 120 个独立包。维护者可以先按榜单次序和实际解算耗时选择场景。若每个包都按 8 MiB 预算，所有包的 gzip 上限合计 960 MiB。一次官方搜索只读当前武器和当前场景对应的一个包。以视使之触 100% 爆头群体首个模板为例，二十个同等成本的包约需 7.84 小时，120 个约需 47.06 小时。这是同成本预算换算，逐武器实测见上表。

首次下载经本机 HTTP 计时。8 MiB 档的整轮实测距十分钟有 114 秒余量，16 MiB 档有 327 秒。清单查询最多 5 秒，正式包的读取与校验默认最多 60 秒。按包大小计算，8 MiB 和 16 MiB 在 60 秒内传完分别至少需要 1.12 和 2.24 Mbit/s，有效带宽还需为握手、解压、索引和存储留出时间。生产应记录实际 CDN 的首次下载和整轮墙钟。

可在同一版本的本地发布目录运行 `node scripts/bench_search_cache.mjs --site site --weapon ocucor --ruler standard_multi_target --out target/bench --budget 8388608,16777216`。输入使用内置模板，单组程序保留原始回执、逐轮摘要、实际战斗次数、gzip 字节数和端到端墙钟。
