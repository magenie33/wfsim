# 官方优化器热缓存实测

2026-11-21 在 Ryzen 7 9700X 上以 10 个 Chromium 计算 Worker 串行运行同一官方请求的各个版本。基线取上游发布 `9fd08b2202`，计算引擎 `d418682f5fce`，数据 `450ebd22f510`。候选引擎为 `8bcade14745b`，WASM 为 `14053539be20`。每轮都检查有序候选分数和最终排名。时间包括本地 HTTP 下载、校验、解压、缺项补算、入围的 1,000 场复测和结果交付。

| 视使之触，25 目标、100% 爆头、四元素 | 冷启动 | 8 MiB | 16 MiB |
| --- | ---: | ---: | ---: |
| 官方空白起点，完整候选池 | 24:48 | 8:06 | 4:33 |
| 额外禁用一张 MOD 和一个赋能，保留空白起点 | 27:14 |  | 12:43 |

第一个官方模板捕获了 43,629 条分片。8 MiB 档发布其中 11,921 条。同配置冷算完成 144,568 场候选评分，热启动补算 81,144 场，再对 10 个入围进行千场复测。捕获并导出用时 23:16.5，生成 8 MiB 热包另用 15.1 秒。这台宿主单独烘焙该武器、该场景、该模板共约 **23:32**。大包和后续预算由同一份宿主回执重复生成。

同一把武器的官方单体 50% 爆头常规搜索，冷算 12.24 秒，0.90 MiB 热包用时 7.71 秒。额外禁用一张卡，12.02 秒降到 7.95 秒。复制为自定义场景后，首次 11.68 秒，重开页面后使用个人 IndexedDB 为 7.81 秒。样本中的 Furis 单体锁定起点，使用空白起点生产的包，20.15 秒变为 20.87 秒，低于 10% 的发布门槛。

可在同一版本的本地发布目录运行 `node scripts/bench_search_cache.mjs --site site --weapon ocucor --ruler standard_multi_target --out target/bench --budget 8388608,16777216`。输入使用内置模板，单组程序保留原始回执、逐轮摘要、实际战斗次数、gzip 字节数和端到端墙钟。
